# 追記方式への本番移行

本番の Google 認証設定と接続先選択を維持し、検証版で確認した行単位の保存方式を導入します。検証用シート固定・localhost 制限・検証用バナーは本番には含めません。

## 切り替え

1. 各端末で進行中の保存を完了し、旧版のタブとスマホ画面をすべて閉じます。
2. 公開後のアプリを開き、初期画面の「Googleシートと連携」から既存の本番シートを読み込みます。移行のための「初期化して書込」は不要です。
3. 最初の通常保存から対象テーブルに管理列を追加し、新規は追記、編集は変更セル、削除は削除フラグとして保存します。既存 ID とデータ行を保持します。
4. 他端末も新しい版で接続します。旧版の全体書き換えと新方式は混在させないでください。

## 保存と整理

通常の削除では会計・過去帳を連鎖削除しません。兼務寺院の完全削除と履歴・削除済みデータの整理は、専用のメンテナンス処理で行います。通常の受付入力・編集では全体統合モーダルを起動せず、変更対象を保存・確認します。

ブラウザ更新後の起動時読込は Google シートを正として読み込みます。未送信の入力を続ける場合は画面更新せず「今すぐ同期」を使用します。

## 不具合があった場合

同期を停止して内容を確認してください。管理列と削除済み行があるシートへ、旧版をそのまま接続し直さないでください。旧版に戻す場合は全端末を停止し、アプリと Google シートの版を対応させて戻す必要があります。

## 検証

本番設定での自動テスト、型チェック、公開用ビルドを実施。旧形式の管理列なしデータからの移行と、新規シートへの初回保存もテスト対象です。本番の実データに対する書込試験は行っていません。

# 再連携時の変更統合

## 使い方

認証切れなどで端末に未送信の編集が残っている場合、データ連携でGoogleへ再ログインすると統合画面を開く。通常の閲覧・監視だけではシートへ書き戻さない。

最初に、他端末の未送信編集を退避し、他端末・別タブのアプリを閉じる。進行中の保存が終わったことを確認し、Googleシートの直接編集も止める。その後、この1台で比較・競合選択・最終確認を行う。他端末に未送信編集があれば、統合完了後にその端末も1台ずつ同じ手順で統合する。端末を初期化して未送信編集を捨てる必要はない。

競合しない項目は自動採用する。同じ項目の異なる編集、同一IDによる新規作成の衝突、削除は利用者が選択する。会計取引や一括会計の同一受付は、金額・収支・科目などの不整合を避けるためまとめて確認する。親の削除と関連データの変更もまとめて選択し、関連先がなくなる選択では確定できない。

「保留して閉じる」はシートへ送信しない。端末の編集と選択途中の内容は保存され、再度データ連携すると確認を再開する。以前の同期基準がない初回は、異なるデータを削除と決めつけず保守的に確認する。

## 保護の仕組み

- シートごとに、最後に確認できた端末側・シート側のスナップショットをIndexedDBへ保存する。端末データの既存の永続保存と合わせ、再読み込み後も未送信の差分を検出する。
- 比較時の読み込みでは案内テンプレート・一括会計設定などを端末へ保存しない。完全な読み込みができなければ中止する。
- 確定直前に全対象データを再取得し、変わっていれば再比較する。選択は比較内容が変わっていない場合だけ引き継ぐ。
- 送信前に、両側の元データと統合案をIndexedDBへ保存する。保存に失敗すれば送信しない。バックアップキーは `sheets_merge_backup_v1:<処理ID>`、確認途中は `sheets_merge_draft_v1:<シートID>`。
- 統合書き込みはデータ更新リクエストを1回だけ送る。タイムアウトなど結果が不明な場合は自動再送せず、次の再連携で実際のシートを確認する。
- 保存後も全対象データを読み戻し、意図したレコードと値を確認してから同期成功とする。確認できなければ元の端末データと退避データを維持し、通常の書き込みを禁止する。
- 古い削除履歴を削除命令として再実行しない。履歴は従来どおり最新1,000件をシートへ保存し、統合前の双方の履歴は統合バックアップに残す。
- 案内テンプレートの文書タイトルも往復で保持するため、シートに「文書タイトル」列を追加する。

## 運用上の限界

これは、他端末を閉じる運用を前提とした方式である。他端末の保存を強制的に止めるサーバー側の排他制御は追加していない。直前確認と書き込みの間の同時更新を技術的に完全排除できないため、統合中の他端末利用やシートの直接編集はしない。全端末を新版へ更新してから使う。

ブラウザーの保存データを消去すると、未送信編集・同期基準・統合バックアップも失われる。Excelなどの外部バックアップも継続する。処理途中にアプリを閉じず、成功またはエラーの表示を待つ。

Google認証設定の変更や、新しいサーバーの設置は不要。認証期限切れは再ログインを案内し、一般的な通信エラーと区別する。データ連携画面がログイン処理を担当している間、認証通知から重複する自動読み込みを開始しない。

## 検証

3者比較、競合選択、親子関係、永続保存、同一IDの衝突、途中の更新・保留・送信結果不明・保存後不一致を自動テストする。実際のSheets変換処理による書き出し・読み戻しも、架空データと模擬通信を使って検証する。本番Googleシートを使った書き込みテストは行わない。

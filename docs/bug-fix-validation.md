# 保存・同期・塔婆ToDoの修正確認

## 変更点

- Googleシート出力は、今回の出力対象の表だけを `spreadsheets.batchUpdate` で置き換えます。消去と書き込みを同じリクエストに入れるため、Google側でリクエストが拒否されても表の消去だけが残りません。独自のメモ・集計シートは更新しません。
- シート名の旧表記、1000行単位のデータ、空欄、古い余剰行も扱います。文字列は文字列として保存し、電話番号の先頭ゼロや改行を維持します。会計金額など数値型の値は数値で保存します。
- 同じ檀家・同日の別法要の塔婆ToDoを上書き・削除しません。法要IDによる紐づけを優先し、旧データの日付による補完は未紐づけの候補が1件の場合に限定します。
- 塔婆ToDoの変更時は、秒単位のシート往復後も旧データより新しくなる更新日時を付けます。法要を削除するときも別法要に紐づいたToDoを維持します。
- 端末保存はIndexedDBトランザクションの確定を待ち、失敗を呼び出し元へ返します。画面に保存失敗と再試行ボタンを表示し、再試行では最新の未保存データを使います。
- 未使用のSMTP送信APIは410で拒否します。画面が現在使っているGmail・メールアプリの起動とクリップボードへのコピーは維持します。SMTP環境変数が残っていてもサーバーからは送信しません。

## 認証・運用設定

Google OAuth、Firebaseプロジェクト、同意画面、要求するGoogle APIスコープの変更はありません。認証設定ファイルも変更しません。サーバーからのSMTP直接送信を外部ツールで利用していた場合は、このAPI終了の影響を受けます。

## 自動検証

```sh
npm install --ignore-scripts
npm test
npm run lint
npm run build
```

10件の回帰テストで、ToDoの取り違え・削除・同期、出力対象の限定、旧シート名、失敗時の消去防止、文字列と数値、保存確定・失敗・再試行、SMTP API停止を確認します。5件の元の問題については、修正前のコードでテストが失敗し、修正後に成功することも確認済みです。

Google API、IndexedDB、SMTPはテスト内で模擬しています。本番のシート・実アカウント・実メールは使用しません。GitHub ActionsではNode 20上でテスト、型チェック、ビルドを実行します。

## 実環境での確認事項

本番反映前に、コピーしたシートでログイン、出力と再読込、2端末のToDo同期を確認してください。シート内のセルの表示書式・保護範囲や、保存容量不足時の各ブラウザーの挙動は環境に依存します。

極端に大きな出力でGoogle APIがリクエストを拒否した場合は同期エラーとして止めます。表を先に消去する分割送信へは戻しません。通信切断で応答だけを受け取れなかった場合、Google側では更新が完了している可能性があります。

## 元に戻す方法

この修正用プルリクエストを取り込む前は、mainのコードは変更されません。取り込み後は修正コミットをrevertするとコードを戻せます。シートのデータを元に戻す場合は別途Excelバックアップを使用します。

# Googleシート読み込み失敗時の書き戻し防止

## 動作

- 起動・再接続・手動読込・操作履歴監視からの同期は読み込み専用。端末とシートをマージして書き戻さない。
- 10秒監視は直近の操作履歴だけを読み、未取得の操作があるときに全データを取得する。履歴に変化がないシート直接編集は、この監視だけでは検出できない。手動読込を使う。
- 全シートの全取得が成功してから端末へ反映する。大きなシートでは2,000行ごとに割り当て済みの最終行まで読み、途中の空白を終端と誤認しない。
- 通信失敗、不正応答、応答範囲の欠落、必須シート・寺院情報の欠落は読込エラー。成功扱いで起動画面を閉じない。既存端末データを取得前に消去しない。
- 各アプリ起動時は書き込み禁止。正常な全件読込と端末反映が完了して初めて、その接続先への通常保存を許可する。読込・監視・保存の失敗では再度禁止し、タイマーで解除しない。
- 読込完了のスナップショットを保存判定の基準にし、画面への反映だけで自動保存を起こさない。
- 監視で変更を検出しても、端末に保存待ちの変更がある場合、または取得中に端末が変更された場合は端末を上書きしない。同期を止めて案内する。必要な端末データをExcelへ退避した後、明示的な「端末データを初期化して読込」で再開する。
- 接続先の404を受けて別のファイルを作成・選択して読み書きしない。

## 意図した変更と範囲

通常の新規作成・編集・削除による保存経路は残すが、全件読込の確認前や失敗後は書き込ませない。

例外は確認画面から実行する「Googleシートを初期化して書込」だけ。この操作はExcelバックアップ等の端末データを正として再構築するため、旧シートの読込成功を要求しない。処理中は通常保存を停止し、初期化書込がすべて成功した後、新しい接続先への通常保存を許可する。失敗時は書込停止を維持する。自動同期・監視からこの例外処理は呼ばない。既存のチュートリアル混入防止・実行確認・同時処理防止は維持する。

読込経由の年度アーカイブ再配置は行わない。年度判定と通常保存時の配置処理は維持する。レコード単位保存・30日保持・サーバー側の複数端末排他は、この変更には含まれない。

旧版やGoogle AI Studio内の別コードからの書き込みは、この修正では止められない。公開版を更新した後、利用する全端末で旧画面を閉じて新しい版を読み込むこと。既にシート自体から失われたデータを復元する機能ではない。

## 検証

自動テストで2ページ目の失敗、途中の空白、欠落応答、必須シート欠落、4,500件の過去帳と会計の完全取得、書き込み禁止の維持、未保存編集の保護、監視の履歴限定取得、読込後の自動保存抑止を検証する。実際の利用者のGoogleシートはテストに使用しない。
